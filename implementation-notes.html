ENG-3885 Implementation Notes

This file is a running record of design decisions, deviations, tradeoffs, and open questions while implementing daemon-owned subagent runtimes.

Design Decisions

  • The main implementation direction is to make runtime-created sessions use the same AgentSessionRuntime abstraction for subagents. The subagent boundary is a host interface that creates a child runtime; the parent AgentSession still owns RLM result shaping and parent usage attribution.
  • Child runtime creation needs internal session overrides so the child inherits the parent's active model, thinking level, scoped model list, active tools, and RLM depth instead of re-resolving CLI/default startup state.
  • AgentSessionRuntime now implements the subagent host. Runtime-created parents bind themselves as the host for their session, so nested rlm() calls create child AgentSessionRuntime instances through the same runtime factory used for top-level session replacement.
  • The parent AgentSession still builds the user-facing rlm_child_update summary and applies child usage attribution. Those are RLM result semantics rather than runtime construction semantics.
  • Child runtimes carry AgentSessionRuntime.metadata with kind: "subagent", parent session id/file, RLM child id, prompt, and session directory. The missing daemon layer can map this onto parentActiveSessionId once its active-session ids exist.

Deviations

  • The current worktree does not contain the daemon orchestrator registry or protocol files described by ENG-3873. This implementation therefore adds the runtime-host boundary and runtime-owned child tracking in core code, but cannot wire a concrete daemon protocol list/attach/kill endpoint or parentActiveSessionId field yet.

Tradeoffs

  • Raw AgentSession callers still need an inline fallback because the public SDK and existing tests can construct sessions without an AgentSessionRuntime. Runtime-created sessions will use the regular runtime host by default.
  • Runtime-created child sessions bind extensions with an empty UI context. This makes the child more like a normal runtime and balances session_start with session_shutdown, but it may expose extension lifecycle behavior that the old inline child path skipped.

Open Questions

  • Once ENG-3873 lands, confirm the daemon retention policy for completed child runtimes: dispose immediately after RLM completion while retaining metadata, or keep the runtime attachable until the parent session is closed.
