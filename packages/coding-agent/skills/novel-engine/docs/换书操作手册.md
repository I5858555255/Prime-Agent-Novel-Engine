# 换书操作手册（跨项目复用 · 只改配置与数据，代码零改动）

> 目标：把引擎从「吸氧证道 / 陆烬」迁到任意新书时，**全部动作都落在配置与数据文件**，
> 不需要改任何 `.py`。代码侧的"书绑定"点已在前一轮全部抽到 config（见 §0），
> 本手册只列你（作者/操作者）要动手做的 12 步 + 校验。

## 0. 代码去绑定已完成（无需再改代码）

| 代码点 | 原先绑定 | 现在读取 | 换书动作 |
|---|---|---|---|
| `chapter_director.OUTLINE_FILENAME` | 写死 `吸氧证道_V2_1_完整大纲.md` | `volumes.json` 顶层 `outline_file` | 改 1 个字段 |
| `chapter_director._parse_outline` 卷标记 | 写死 10 条陆烬卷名 | `volumes.json` 每卷 `outline_marker`（缺省按 title 生成） | 改 title 即可，或显式填 marker |
| `chapter_director._parse_author_intent` 阶段标记 | 写死 10 条陆烬阶段名 | `volumes.json` 每卷 `intent_marker`（缺省按 title 生成） | 同上 |
| `writer_agent.SCENE_SYSTEM_PROMPT` 视角行 | 写死"以陆烬为主视角" | `bible/style_bible.md` 第一条含"视角"行 | 改 style_bible 视角行 |
| `reviewer_agent` 婴儿卷硬约束 | 写死陈老根 ch1-9 约束 | `project_constraints.yaml` `review_hard_constraints` 段 | 改/删该段 |

**严格模式**：`volumes.json` 一旦提供卷数据，就**必须**写顶层 `outline_file`，否则
`chapter_director` 显式报错（不静默回退陆烬文件名）；`volumes.json` 整个缺失时才回退
`OUTLINE_FILENAME` 旧文件名（兼容最小测试夹具/旧数据）。

缺省回退：其余配置（marker/视角/硬约束）缺失时，代码回退到**当前陆烬书**的内置默认值。
新书只要把对应配置填上，就会覆盖默认。

## 1. 引擎根目录（数据根）

```
packages/coding-agent/skills/novel-engine/src/novel_engine/
```
下文所有相对路径（`bible/`、`config/`、`docs/`）都基于这里。

## 2. 十二步迁移清单（按顺序）

### Step 1 · 写新书大纲 md
- 路径：`docs/<你的书名>_完整大纲.md`
- 内容：十卷（或 N 卷）八要素 + 每卷逐章任务表（`| 章 | 核心任务 |`）。
- 卷标题写法需与 Step 2 的 `outline_marker` 一致（缺省会自动按 `## 四、第一卷《<title>》` 生成，
  你的大纲里卷标题必须匹配；最稳妥是**显式在 volumes.json 写 `outline_marker`**）。

### Step 2 · 改 `config/planning/volumes.json`（单一权威源）
- 顶层加 `"outline_file": "<你的大纲文件名>"`。
- 每卷：`id`（V01…）、`title`、`chapter_range`、`theme`、`core_conflicts`、`climax_chapter`、`climax_description`。
- 可选：`outline_marker` / `intent_marker`（卷标题原文；缺省按 title 生成）。
- 这是换书**最核心**的一个文件，代码所有卷解析都读它。

### Step 3 · 写 bible 五件套（`bible/*.md`）

> 复制 `bible/_TEMPLATE_换书bible.md` 为 5 个 `<name>_bible.md`，按勾选项填。
> `style_bible.md` 第一行写视角；`author_intent.md` 阶段标题必须与 `volumes.json` 的 `intent_marker` 匹配。
| 文件 | 内容 | 体量建议 |
|---|---|---|
| `world_bible.md` | 世界观/地理/力量体系/核心规则 | ≤2KB |
| `character_bible.md` | 人物档案（C001…）+ 认知/信息边界 + 关系表 | ≤1.5KB/角色 |
| `style_bible.md` | **第一行写视角**（如"第三人称有限视角，以主角XXX为主视角…"）+ 文风/断句 | ≤1KB |
| `author_intent.md` | 按"## 第N阶段：xxx（第A-B章）"切卷，每阶段 forbidden 条款 + 锚点 | 不限 |
| `ending_bible.md` | 终局 + 伏笔回收窗口（F001…） | 不限 |

> `style_bible.md` 的第一条含"视角"行会被 writer 注入场景系统提示；
> `author_intent.md` 的阶段标题需与 volumes.json 的 `intent_marker` 匹配。

### Step 4 · 写 `config/planning/plot_graph.json`
- `nodes[]`：每个剧情节点 `{id, chapter_target, description}`。有节点章由它直接驱动。
- 无节点章才走中纲（Step 7）。

### Step 5 · 写 `config/planning/decision_rules.json`（R 条款化判例）
- 每条 `{name, scale(forbidden/allowed/hint), pattern, rule_applies(vols/chapter_range), covers_clauses}`。
- 与 `bible/decision_rules.md` 同步维护（md 给人看，json 给引擎判）。
- 缺判例的卷在对应卷批次进入时覆盖审计会挂起（防漏判，不静默放行）——可后置补。

### Step 6 · 写 `config/foreshadow/registry.json` + `config/planning/character_registry.json`
- 伏笔权威注册表：`{fid, id(legacy F编号), plant_chapter, resolve_chapter, importance, anchors[]}`；
  与 `ending_bible.md` 伏笔窗口同步。
- 角色登记：已登记角色清单，中纲 `characters` 里不在清单的专名/C编号 → 标"新角色待登记"。

### Step 7 · 生成 + 审计中纲（无节点章）
```powershell
cd packages\coding-agent\skills\novel-engine\src
python -X utf8 -m novel_engine.scripts.generate_mid_outline --vid V01 --start <起> --end <止>
python -X utf8 -m novel_engine.scripts.outline_repair  config/planning/mid_outline_V01_ch<起>-<止>.json
python -X utf8 -m novel_engine.scripts.audit_mid_outline config/planning/mid_outline_V01_ch<起>-<止>.json
```
- 中纲领先生成进度 ≥1 片；批间保留审计。

### Step 8 · 填 `config/constraints/project_constraints.yaml`
| 段 | 换书动作 |
|---|---|
| `a_route_patterns` | 改主角/独修者姓名 + 正则（或整段删） |
| `anchor_phrases` | 按新伏笔 fid 填锚点短语 |
| `compliance_note` | 合规尾注（追加锚点时写 boundary_note） |
| `character_replacements` | 中纲 characters 未登记 token → 角色编号 |
| `review_hard_constraints` | reviewer 婴儿卷/初期卷额外扣分项（不填回退陆烬默认） |

### Step 9 · 清运行时状态（**必须**）
```powershell
Remove-Item -Recurse -Force src\novel_engine\runtime\*
Remove-Item -Recurse -Force src\novel_engine\chapters\*
# 保留 config/、bible/、docs/、scripts/；只清 runtime（checkpoint/state.db/日志）与 chapters（产物）
```
- 不 clear 会让旧书的 world_state / checkpoint 串进新书。

### Step 10 · 换 `.env` key + `llm_providers.json` profile
- `src/novel_engine/.env`：新书用的 API key（`AGNES_TOKEN_API_KEY` 或对应供应商）。
- `config/llm_providers.json`：`active` profile 指向新供应商；token plan 限额按需调 `plan_limits`。

### Step 11 · 初始化世界状态 + 冒烟
```powershell
python -X utf8 -m novel_engine.agent_api init_state   # 或 run_volume 首跑自动 init
python -X utf8 -m novel_engine.scripts.run_volume --chapters 5 --resume   # 冒烟 5 章
python -X utf8 -m novel_engine.scripts.status_snapshot
```
- 5 章冒烟通过（COMMITTED 且过门禁）再放量。

### Step 12 · 放量 + 看护
```powershell
python -X utf8 -m novel_engine.scripts.run_volume --chapters <总> --resume
pythonw -X utf8 -m novel_engine.scripts.relay_watchdog --final-cap <总> --initial-target 0
```

## 3. 校验清单（迁移完成前逐条过）

- [ ] `volumes.json` 顶层 `outline_file` 已填且指向的大纲 md 存在，每卷 `outline_marker` 能在大纲里 `find` 到（严格模式：volumes.json 有卷数据就必须填 `outline_file`，否则 director 报错）。
- [ ] `author_intent.md` 每个阶段标题与 volumes.json `intent_marker` 匹配。
- [ ] `style_bible.md` 第一行含"视角"（否则 writer 回退陆烬视角）。
- [ ] `decision_rules.json` 覆盖各卷 forbidden（`audit_mid_outline` 覆盖审计 K=0 或挂起待补）。
- [ ] `foreshadow/registry.json` 的 fid 与 `project_constraints.yaml` `anchor_phrases` 一致。
- [ ] `runtime/` 与 `chapters/` 已清空（无旧书残留）。
- [ ] 5 章冒烟 COMMITTED + 门禁通过 + `status_snapshot` 连续进度正确。

## 4. 仍属"按书重写"、无法靠配置消除的部分（明确告知）

以下**本质是创作内容**，换书必须人工重做，不属于代码绑定，不在"只改配置"承诺内：
- `bible/*.md` 五件套（世界观/人设/文风/意图/结局）——创作输入。
- `plot_graph.json` / `decision_rules.json` / `foreshadow/registry.json` / `character_registry.json`——剧情规划。
- 大纲 md 本身。
- 测试夹具（`tests/` 里以陆烬数据断言的用例）——测试不是运行路径，换书不必全改，
  但跑全量门禁时这些夹具仍针对陆烬书（引擎代码已去绑定，夹具保持原样不影响新书运行）。

> 一句话：**引擎代码 = 书无关；配置 + 创作数据 = 按书重写。** 本手册 12 步覆盖前者，
> 后者的 bible/规划/大纲是创作活，手册只给字段模板，不替你写剧情。
