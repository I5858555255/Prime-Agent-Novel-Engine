# Novel-Engine 使用方法指南

## 一、项目概述

Novel-Engine 是基于 Prime-Agent 底座构建、面向长篇网络小说创作的高性能 AI 流水线与状态机。通过代码级精确状态检索、持久化分支会话管理、递归子智能体并发、以及场景级自适应缝合修补，实现全自动、高质量的章节编译与长线控制。

本项目已应用于长篇仙侠小说《吸氧证道：阴阳逆碳，我以人道定仙天》（3000+章）的生成与迭代。

---

## 二、环境要求

- **Python**: 3.12+
- **Poetry**: 2.x（用于依赖管理）
- **LLM API**: SiliconFlow / Qwen（`https://api.siliconflow.cn`）或兼容 OpenAI 接口

## 三、安装与配置

### 3.1 进入项目目录

```bash
cd D:/AI/Prime-Agent-Novel-Engine/Prime-Agent-Novel-Engine/packages/coding-agent/skills/novel-engine
```

### 3.2 安装依赖

```bash
poetry install
```

### 3.3 配置 LLM API 密钥

编辑 `src/novel_engine/config/runtime_config.json`：

```json
{
  "llm": {
    "provider": "openai",
    "model": "Qwen/Qwen3.5-4B",
    "api_base": "https://api.siliconflow.cn",
    "api_key": "YOUR_API_KEY",
    "temperature": 0.85,
    "max_tokens": 16384,
    "timeout_seconds": 120,
    "use_mock": false
  }
}
```

或使用环境变量覆盖：`ZLEAP_MODEL_API_KEY` / `ZLEAP_API_KEY`。

## 四、运行模式

### 4.1 Mock 模式测试（无需 API Key）

```bash
cd src
poetry run python -m novel_engine.tests.mini_test_runner
```

- 完全离线，使用确定性模板回复
- 10 章生成约 5-8 秒
- 用于验证流水线逻辑、状态机、回滚机制

### 4.2 真实 API 测试

```bash
cd src
poetry run python -m novel_engine.tests.mini_test_runner --real
```

- 连接 SiliconFlow / Qwen API 进行真实章节生成
- 每章约需 2-5 分钟（取决于场景数与并发）
- 输出至 `chapters/` 目录

### 4.3 长线测试（70章滑动窗口审查）

```bash
cd src
poetry run python -m novel_engine.tests.medium_test_runner
```

- 检测套路重复、节奏平淡、伏笔搁置等长线问题
- 每 50 章自动汇总审查反馈

### 4.4 单元测试

```bash
cd src
poetry run python -m unittest novel_engine.tests.test_novel_engine -v
```

## 七、核心工作流

```
INIT
  ↓
PLANNING    ← 结合 plot_graph 划定当前章节线索与目标
  ↓
WORLD_SIM   ← 预估世界/角色状态变更，锁定约束
  ↓
DIRECTING   ← 生成任务卡（含 Scene Blueprints）
  ↓
SYNOPSIS    ← 编写剧情提纲，提取状态跃迁
  ↓
WRITE_SCENE ← 递归并发编写具体场景正文
  ↓
POLISH      ← 文风、叙事张力润色
  ↓
REVIEW      ← 六维评分
  ├── score ≥ 85 → PASS → COMMIT → NEXT_CHAPTER
  ├── 60 ≤ score < 85 → FIX → 局部缝合重试（最多3次）
  └── score < 60 → 回退 PLANNING（最多3次，耗尽则 NEEDS_HUMAN）
```

### 六维评分标准

| 维度 | 权重 | 说明 |
|------|------|------|
| 剧情一致性 | 25% | 是否遵循 plot_graph 节点目标与伏笔计划 |
| 人物一致性 | 20% | 角色行为/语气/境界是否与 world_state 一致 |
| 伏笔执行 | 20% | clue_plan 写作指令是否在正文中体现 |
| 文风符合度 | 15% | 是否遵循 style_bible.md 的叙事视角与语言风格 |
| 节奏控制 | 10% | 场景切换、情绪曲线是否符合任务卡设计 |
| 创新亮点 | 10% | 是否有超出模板的生动细节或意外转折 |

## 八、故障恢复策略

| 错误类型 | 处理策略 |
|----------|----------|
| `json_parse_error` | 自动重试 LLM prompt 微调（最多3次），耗尽后降级为半自动手动修正 |
| `api_disconnect` | 指数退避等待（`wait_and_retry`），保障长任务无人值守安全继续 |
| `context_overflow` | 自适应检测，动态收缩滑动窗口 |
| `world_state_conflict` | 读取 `runtime/checkpoint.json` 进行 Git 式快照回滚，标记 `NEEDS_HUMAN` |

## 十、自定义新小说

### 10.1 世界观
编辑 `bible/world_bible.md`，控制在 2000 字符内，包含：时代背景、地理格局、势力分布、力量体系、关键规则。

### 10.2 人物
编辑 `bible/character_bible.md`，核心人物 5-7 个，ID 格式 C001, C002...

### 10.3 卷纲
编辑 `planning/volumes.json`，定义每卷的章节范围、主题、核心冲突、高潮章。

### 10.4 剧情 DAG
编辑 `planning/plot_graph.json`，按章节目标添加节点，指定依赖关系与伏笔关联。

### 10.5 伏笔
编辑 `foreshadow/registry.json`，定义埋设章、暗示点、回收章、重要性（0-1）。

## 十二、常见问题

**Q: 如何切换到新小说项目？**
A: 替换 `bible/` 和 `planning/` 目录内容，运行 `cd src && poetry run python -m novel_engine.tests.mini_test_runner --real` 验证。

**Q: 如何从中断处继续生成？**
A: 使用 `scripts/start.sh resume <章节号>` 或修改 `runtime/state_machine.json` 中的 `current_chapter`。

**Q: 如何查看实时生成进度？**
A: 启动 Web 控制台 `scripts/start.sh dashboard`，访问 http://localhost:8080。

**Q: 如何调整评分阈值？**
A: 编辑 `config/quality_thresholds.json` 中的 `pass`（默认85）和 `fix`（默认60）值。
