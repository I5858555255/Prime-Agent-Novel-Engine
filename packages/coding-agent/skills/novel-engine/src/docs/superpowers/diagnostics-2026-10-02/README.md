## 封存原因（用户判断 + 复核证据）

ch21-50 试跑三轮后仍有 2 章失败（ch25/ch48），且暴露两类**疑似架构级盲区**，
非单点补丁可覆盖：

### 盲区 1：发布判定拒绝原因不落盘（ch48）

- ch48 连续两次失败：`score=86.4`（第二轮）→ `score=75.3`（第三轮重跑）。
- 两次 END note 均为 `hard gate []`（无 leak/det/review 硬项），段日志仅 START/END/errors 三行
  （run_volume 日志粒度即如此，非异常），**发布拒绝的具体原因（evaluate_publish 的
  nonscore reasons / has_high 明细 / force-best 未触发的条件）不在任何持久化记录中**。
- 结论：`_decide_publish`（pipeline_orchestrator.py L1380-1436）的拒绝路径缺少
  verdict 明细落盘；`run_volume` END note 只含 hard gate 列表。这是可观测性缺口——
  无法回答"为什么 75.3 分且无硬项的章被拒绝"。

### 盲区 2：泄漏检测是"修炼词表级"而非"世界观信息分级"（ch48 正文泄漏）

- ch48 最终正文（final_gate_reject.txt，11KB）含大量转世设定直写：
  - "前世在病床上，他见过太多这样的沉默——医生的回避、护士的欲言又止"
  - "前世是看得见的囚笼，今生却是看不见的枷锁"
  - "如今重活一世，有了健康的躯壳"
- 这些词（前世/病床/医生/重活）**不在任何 leak 词表**（infant.json hard_block 全是修炼词），
  review/det 亦不覆盖 → 无 hard gate，正文泄漏通过全部检测。
- 根因：泄漏检测机制（concept_unlocks + hard_block）只针对"修炼体系/身份揭示"一类
  词汇，对"主角转世身世"这类核心设定的过早暴露**无概念级检测**。若 bible 设定
  （author_intent.md 132 行，无"前世/转世/重生/穿越"字样）要求身世逐步揭示，
  则该泄漏无任何防线。
- 注意：bible 无转世字样——"陆烬是转世者"是 LLM 依据中纲/上下文自行发挥，
  还是大纲设定（吸氧证道 V2.1 大纲需另行核对），是架构级分析的第一问题。

### 盲区 3：内容质量失败无修复通道（ch25/ch48 的"真质量"失败）

- ch25：`[命名矛盾] 活井（古井）与枯井同章共现`（ch15 同款问题再现）——LLM 写作
  不一致，非词表问题，重跑靠随机。
- ch48：75.3 低分——reviewer 判分低（场景结构混乱，partial jsonl 显示场景 2/3/4
  多轮重排），fix loop 无法把低分拉到 88 线。
- 结论：质量类失败依赖"重跑碰运气"，无确定性修复路径；规模化（3600 章）下
  这类失败率会线性累积。
